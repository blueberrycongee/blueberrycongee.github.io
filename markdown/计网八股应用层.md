# 第二章：应用层核心考点全覆盖

## 1. HTTP 协议演进 (Highest Priority)

**① 核心概念解析**
这是面试的“必考题”，要求你清楚 HTTP 各个版本解决了什么痛点。

| 版本 | 核心特性 | 解决的问题 / 存在的不足 |
| --- | --- | --- |
| **HTTP/1.0** | 短连接：每次请求都要建立 TCP 连接 | **不足**：连接无法复用，开销巨大。 |
| **HTTP/1.1** | **长连接 (Keep-Alive)**、管道化 (Pipelining) | **进步**：减少连接建立开销。**不足**：队头阻塞 (HoL Blocking)。 |
| **HTTP/2.0** | **二进制分帧、多路复用**、首部压缩 (HPACK)、服务端推送 | **进步**：彻底解决 HTTP 层的队头阻塞，提升并发。 |
| **HTTP/3.0** | **基于 QUIC 协议 (UDP)** | **进步**：解决 TCP 层的队头阻塞，支持连接迁移。 |

**② 深度追问：什么是 HTTP/2 的多路复用？**

* **解释**：在一个 TCP 连接中，数据被拆分为多个“帧”，这些帧可以乱序发送。接收方根据帧头部的流 ID 重新组装。
* **对比**：1.1 版本必须等前一个请求响应完了才能发下一个（按序），2.0 不需要等待，真正实现了并发。

**③ 避坑指南**

* **误区**：认为 HTTP/2 解决了所有队头阻塞。
* **纠正**：HTTP/2 解决了 **HTTP 层** 的阻塞，但如果底层 TCP 丢了一个包，整个 TCP 连接仍会由于重传机制而阻塞。这正是 **HTTP/3 切换到 UDP (QUIC)** 的根本原因。

## 2. HTTPS 与 TLS 握手 (Highest Priority)

**① 核心概念解析**
HTTPS = HTTP + SSL/TLS。其核心在于：**对称加密传输数据 + 非对称加密交换密钥 + 数字证书验证身份**。

**② TLS 1.2 握手过程 (简明版)**

1. **Client Hello**：客户端发送支持的协议版本、随机数 、加密套件列表。
2. **Server Hello**：服务端确认协议、发送随机数 、**数字证书**。
3. **密钥交换**：客户端验证证书有效性，生成随机数 。用证书里的**公钥**加密后发给服务端。
4. **生成主密钥**：双方利用  计算出**对话密钥**（对称密钥）。
5. **结束**：后续通信全部使用该对称密钥加密。

**③ 常见面试追问**

* **为什么不一直用非对称加密？** 因为非对称加密运算量太大，效率极低。
* **数字证书里有什么？** 签发机构、有效期、公钥、持有者信息、以及数字签名。
* **证书如何防止被伪造？** 证书包含签名，是用 CA 机构的私钥对证书内容进行哈希后加密生成的。客户端用集成在系统里的 CA 公钥去解密验证。

## 3. HTTP 状态码 (High Priority)

要求能准确说出每一类的含义及代表性状态码。

* **2xx (成功)**：
* 200 (OK)：请求成功。
* 204 (No Content)：成功但没有内容返回。
* 206 (Partial Content)：断点续传/分块下载。


* **3xx (重定向)**：
* 301 (Moved Permanently)：永久重定向（SEO 友好）。
* 302 (Found)：临时重定向。
* 304 (Not Modified)：命中协商缓存（面试高频）。


* **4xx (客户端错误)**：
* 400 (Bad Request)：请求参数错误。
* 403 (Forbidden)：服务器禁止访问。
* 404 (Not Found)：资源不存在。


* **5xx (服务端错误)**：
* 500 (Internal Server Error)：服务器崩了。
* 502 (Bad Gateway)：网关/代理从上游收到了无效响应。
* 503 (Service Unavailable)：服务器忙或维护。

* **⭐ HTTP状态码命名规律**：
* **首位数字表示类别**：1xx(信息)、2xx(成功)、3xx(重定向)、4xx(客户端错误)、5xx(服务端错误)
* **后两位数字表示具体状态**：按RFC标准定义，不是随意编号
* **为什么没有501？** 501确实存在(Not Implemented)，只是面试中不常考。其他如504(Gateway Timeout)等也都是有效的状态码

## 4. DNS 域名解析 (High Priority)

**① 核心概念解析**
将域名（如 `www.google.com`）转化为 IP 地址。

**② 查询过程**

* **递归查询**：客户端问运营商 DNS，运营商 DNS 负责跑腿去问别的服务器，最后直接把结果给客户端。
* **迭代查询**：运营商 DNS 先问根域名服务器（获得 .com 位置），再问 .com 服务器（获得 https://www.google.com/search?q=google.com 位置），最后问 https://www.google.com/search?q=google.com 授权服务器。

**③ 避坑指南**

* **`▽` DNS 劫持**：攻击者修改 DNS 解析结果。
* **`▽` DNS over HTTPS (DoH)**：通过加密的 HTTPS 发送 DNS 请求，防止被监听或篡改。

---

## 5. Cookie / Session / Token (Medium Priority)

* **Cookie**：保存在**浏览器**，每次请求自动携带。容易受到 CSRF 攻击。
* **Session**：保存在**服务器**。服务器通过 Cookie 里的 `SessionID` 来辨认用户。缺点是难以水平扩展（多台服务器间同步难）。
* **Token (如 JWT)**：**无状态**。服务器不需要存，直接解密验证。适合跨域和移动端应用。

---

## 6. WebSocket 协议 (Medium Priority)

**① 核心概念解析**
一种在单个 TCP 连接上进行**全双工**通信的协议。

* **特点**：建立连接时借用 HTTP 协议（Upgrade 头部），连接成功后直接走 TCP。
* **应用**：实时聊天、在线协作、股票实时看板。

---

## 7. 低频与超低频考点 (Low Priority)

* **`▽` HTTP 缓存机制 (中高频，前端必考)**：
* **强缓存**：`Expires` (绝对时间), `Cache-Control` (相对时间)。
* **协商缓存**：`Last-Modified` / `If-Modified-Since` 和 `ETag` / `If-None-Match`（ETag 优先级更高）。


* **`▽` GET 和 POST 的区别**：
* 表面：GET 在 URL 传参，POST 在 Body；GET 有长度限制。
* 底层：都是 TCP。主要区别在于 **GET 是幂等的且可缓存**，POST 不幂等。


* **`▽▽` FTP 协议**：文件传输协议，控制连接 (21) 和数据连接 (20) 分离。
* **`▽▽` SMTP / POP3 / IMAP**：邮件协议。SMTP 发邮件，POP3/IMAP 收邮件。
* **`▽▽` HTTP 请求头/响应头字段**：如 `Host`, `User-Agent`, `Accept`, `Server`, `Date` 等。

## 8. 应用层常见面试追问总结

* **问：输入 URL 到显示页面的全过程？**
* *提示：这是一个综合题，涵盖 DNS -> TCP 握手 -> HTTP 请求 -> 渲染。*


* **问：为什么 HTTP 3.0 要放弃 TCP 而改用 UDP？**
* 答：TCP 在不稳定网络下的队头阻塞、建立连接慢（需要握手）、不支持连接迁移（换 WiFi 就掉线）。QUIC 通过在 UDP 之上自建可靠性，完美解决了这些痛点。


## 9. 面试问答集锦

### 1. HTTP 协议演进

#### **面试官常问问题：**

**Q1: 请说说 HTTP/1.0、HTTP/1.1、HTTP/2、HTTP/3 的区别？**
- **标准回答：**
  - HTTP/1.0：短连接，每次请求都建立新的 TCP 连接，开销巨大
  - HTTP/1.1：长连接（Keep-Alive），管道化（pipelining），但存在队头阻塞
  - HTTP/2：二进制分帧，多路复用，首部压缩，服务端推送，解决 HTTP 层队头阻塞
  - HTTP/3：基于 QUIC（UDP），解决 TCP 层队头阻塞，支持连接迁移

**Q2: 什么是 HTTP/2 的多路复用？它解决了什么问题？**
- **标准回答：**
  - 多路复用：在一个 TCP 连接上，将数据拆分为二进制帧，不同请求的帧可以交错传输
  - 解决问题：HTTP/1.1 的队头阻塞问题，允许并发请求而不需要等待前一个响应

**Q3: HTTP/2 有什么缺点？为什么还需要 HTTP/3？**
- **标准回答：**
  - HTTP/2 缺点：虽然解决了 HTTP 层的队头阻塞，但底层 TCP 仍存在队头阻塞
  - 当 TCP 丢包时，整个连接被阻塞，影响所有流
  - HTTP/3 基于 UDP 的 QUIC 协议，每个流独立，丢包不影响其他流

#### **深度追问：**

**追问1: HTTP/2 的队头阻塞具体表现在哪里？**
- **标准回答：** HTTP/2 在单个 TCP 连接上复用多个请求，但 TCP 保证有序传输。如果中间一个数据包丢失，整个 TCP 连接会等待重传，导致所有流都被阻塞。

**追问2: 为什么 TCP 会出现队头阻塞，而 UDP 不会？**
- **标准回答：** TCP 是面向字节流的协议，必须保证数据的有序和可靠传输，一旦中间数据包丢失，后续数据包必须等待。UDP 是无连接的，每个数据包独立传输，不保证顺序。


### 2. HTTPS 与 TLS 握手

#### **面试官常问问题：**

**Q1: 请详细描述 TLS 握手过程？**
- **标准回答：**
  1. Client Hello：客户端发送支持的 TLS 版本、随机数、加密套件列表
  2. Server Hello：服务端确认协议版本、发送随机数、数字证书
  3. 密钥交换：客户端验证证书，生成 Pre-Master Secret，用公钥加密发送
  4. 主密钥生成：双方用三个随机数生成主密钥
  5. 加密通信：后续通信都用主密钥加密

**Q2: 为什么要用对称加密和非对称加密混合的方式？**
- **标准回答：**
  - 非对称加密：用于安全地交换对称密钥，但计算开销大，效率低
  - 对称加密：用于实际数据传输，效率高
  - 混合使用：既保证安全性，又保证传输效率

**Q3: 数字证书如何防止中间人攻击？**
- **标准回答：**
  - 证书包含 CA 的数字签名
  - 客户端用预装的 CA 公钥验证签名
  - 如果是中间人伪造的证书，签名验证会失败

#### **深度追问：**

**追问1: TLS 1.2 和 TLS 1.3 有什么区别？**
- **标准回答：** TLS 1.3 减少了握手次数（从 2-RTT 减到 1-RTT），移除了不安全的加密算法，支持 0-RTT 恢复连接。

**追问2: 什么是证书链？如何验证？**
- **标准回答：** 证书链是从服务器证书到根证书的完整路径，客户端需要验证每级证书的有效性、签名和信任链。


### 3. HTTP 状态码

#### **面试官常问问题：**

**Q1: 常见的 HTTP 状态码有哪些？**
- **标准回答：**
  - 2xx：200（成功）、204（无内容）、206（部分内容）
  - 3xx：301（永久重定向）、302（临时重定向）、304（未修改）
  - 4xx：400（请求错误）、403（禁止访问）、404（未找到）
  - 5xx：500（服务器错误）、502（网关错误）、503（服务不可用）

**Q2: 301 和 302 有什么区别？**
- **标准回答：** 301 是永久重定向，浏览器会缓存重定向结果；302 是临时重定向，不会缓存。

**Q3: 304 状态码的原理是什么？**
- **标准回答：** 客户端发送带 If-Modified-Since 或 If-None-Match 的请求，服务器发现资源未变化，返回 304，客户端使用缓存。


### 4. DNS 域名解析

#### **面试官常问问题：**

**Q1: DNS 查询过程是怎样的？**
- **标准回答：**
  1. 本地 DNS 缓存查询
  2. 递归查询：本地 DNS 服务器向根域名服务器查询
  3. 迭代查询：根服务器返回 .com 服务器地址，再查询 .com 服务器获得 google.com 服务器地址
  4. 最终获得 IP 地址

**Q2: DNS 缓存机制是怎样的？**
- **标准回答：** 浏览器缓存 -> 操作系统缓存 -> 本地 DNS 服务器缓存 -> 递归查询，TTL 控制缓存时间。

#### **深度追问：**

**追问1: 什么是 DNS 劫持？如何防范？**
- **标准回答：** DNS 劫持是攻击者修改 DNS 解析结果，将域名解析到恶意 IP。防范措施包括 DNS over HTTPS (DoH) 和 DNS over TLS (DoT)。

**追问2: DNS 查询是 TCP 还是 UDP？**
- **标准回答：** 通常使用 UDP（端口 53），因为查询响应数据小。当响应数据超过 512 字节时会使用 TCP。


### 5. Cookie / Session / Token

#### **面试官常问问题：**

**Q1: Cookie、Session、Token 的区别？**
- **标准回答：**
  - Cookie：存储在浏览器，每次请求自动携带，易受 CSRF 攻击
  - Session：存储在服务器，通过 Cookie 中的 SessionID 识别用户，难以水平扩展
  - Token：无状态，服务器不存储，通过 JWT 等验证，适合分布式系统

**Q2: 如何防止 CSRF 攻击？**
- **标准回答：** 使用 CSRF Token、SameSite Cookie 属性、验证 Referer 头部、使用 POST 而非 GET。

**Q3: JWT 的优缺点？**
- **标准回答：** 
  - 优点：无状态，适合分布式，自包含
  - 缺点：无法主动失效，Token 过大，需要额外的安全措施


### 6. WebSocket 协议

#### **面试官常问问题：**

**Q1: WebSocket 和 HTTP 有什么区别？**
- **标准回答：**
  - HTTP：请求-响应模式，短连接或长连接，单向通信
  - WebSocket：全双工通信，持久连接，双向通信

* **⭐ 全双工含义**：
* **半双工**：对讲机模式，同一时间只能一方说一方听
* **全双工**：电话模式，双方可以同时说话和听话
* **HTTP是半双工**：客户端发请求→服务器响应→客户端再发请求
* **WebSocket是全双工**：客户端和服务器可以随时互相发送消息，不需要等待对方

**Q2: WebSocket 如何建立连接？**
- **标准回答：** 先发送 HTTP 请求，包含 Upgrade 头部升级协议，服务器同意后建立 WebSocket 连接，后续直接传输数据。

#### **深度追问：**

**追问1: WebSocket 如何处理心跳机制？**
- **标准回答：** 通过 ping/pong 帧维持连接，检测连接是否存活，防止因网络问题导致的连接中断。


### 7. HTTP 缓存机制

#### **面试官常问问题：**

**Q1: HTTP 缓存有哪些类型？**
- **标准回答：**
  - 强缓存：Expires、Cache-Control，直接使用本地缓存
  - 协商缓存：Last-Modified/If-Modified-Since、ETag/If-None-Match，需要服务器验证

**Q2: ETag 和 Last-Modified 有什么区别？**
- **标准回答：** ETag 基于内容生成，更精确，优先级更高；Last-Modified 基于时间戳，精度较低。

#### **深度追问：**

**追问1: 如何设置合适的缓存策略？**
- **标准回答：** 静态资源使用强缓存（Cache-Control: max-age=31536000），动态资源使用协商缓存。


### 8. 综合性面试问题

**Q1: 从输入 URL 到页面显示的全过程？**
- **标准回答：**
  1. DNS 解析获取 IP 地址
  2. 建立 TCP 连接（可能需要 TLS 握手）
  3. 发送 HTTP 请求
  4. 服务器处理请求并返回响应
  5. 浏览器解析 HTML、CSS、JS
  6. 构建 DOM 树、CSSOM 树、渲染树
  7. 页面渲染显示

**Q2: 为什么 HTTP/3 要使用 UDP 而不是 TCP？**
- **标准回答：** TCP 的队头阻塞问题无法解决，UDP 无连接无序传输，QUIC 在应用层实现可靠性，解决了 TCP 的队头阻塞，支持连接迁移。

**Q3: 如何优化页面加载速度？**
- **标准回答：** 
  - 使用 HTTP/2 多路复用
  - 启用 GZIP 压缩
  - 设置合适的缓存策略
  - 使用 CDN 加速
  - 减少 HTTP 请求数量（资源合并）
  - 使用预加载（preload、prefetch）

**应用层总结：**
这一章的精髓在于 **“效率”与“安全”**。HTTP/2 和 3 是在卷效率，HTTPS 是在卷安全。
