发表一些拙见

由于目前 AI coding 几乎已经完全接管，所以注释这件事实际上成为 harness 的一环，我们要面对的问题应该是：注释怎么写才是让后续的模型更好理解我们的代码系统。

我认为有几个良好的原则：

1. 不写废话注释——代码本身是可自解释的
2. 不写指令型注释——比如 TODO，这会干扰 agent 工作
3. 写明确的 tradeoff

这里可以小小的举个例子：我在开发一个 agent 软件的前端的部分的时候，前端会展示一些工作状态，但是其目的是缓解用户的等待焦虑，所以实际上这个显示状态是和真实的状态不一致的。这里就值得写入一条注释解释这件事，否则 agent 读到这块的代码会很简单的判定为 bug。
